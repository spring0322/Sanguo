# 需求文档

## 介绍

本规范解决了在 Net8 AOT 优化调查中发现的剩余关键问题。重点是确保完全的 AOT 兼容性，通过现代 .NET 8 功能提高性能，并在可能的情况下保持向后兼容性。这些修复将完成 AOT 优化工作并解决 WorldOfTheThreeKingdoms 游戏引擎中的性能瓶颈。

## 术语表

- **AOT**: 提前编译 (Ahead-of-Time compilation)，一种将应用程序编译为本机代码的 .NET 部署模型
- **系统**: WorldOfTheThreeKingdoms 游戏引擎及相关组件
- **插件服务**: 负责动态加载的 PluginService 组件
- **JSON 序列化器**: System.Text.Json 序列化系统
- **随机数生成器**: 随机数生成组件
- **正则表达式引擎**: 正则表达式处理组件
- **传统 JSON**: Newtonsoft.Json 序列化系统（已弃用）

## 需求

### 需求 1: 移除动态类型系统

**用户故事:** 作为一名开发人员，我希望移除所有动态类型实例化和反射代码，以便应用程序完全兼容 AOT。

#### 验收标准

1. 当系统启动时，系统不得尝试使用 Assembly.LoadFrom 动态加载程序集
2. 当系统初始化插件时，Plugin_Service 不得使用 Activator.CreateInstance 创建对象
3. 当系统处理任何组件时，系统不得依赖运行时反射进行类型实例化
4. 当执行 AOT 编译时，系统应成功编译且没有与动态类型相关的裁剪警告
5. 如果需要动态功能，系统应使用 AOT 兼容的替代方案，如源生成器或静态工厂方法

### 需求 2: 清理传统 JSON 系统

**用户故事:** 作为一名开发人员，我希望完全移除 Newtonsoft.Json 依赖项，以便系统仅使用 System.Text.Json 进行序列化。

#### 验收标准

1. 当系统构建时，系统不得引用 Newtonsoft.Json 程序集
2. 当 TextMessageTable 处理数据时，系统应使用 System.Text.Json 转换器而不是 Newtonsoft.Json 转换器
3. 当 WorldOfTheThreeKingdomsEditor 项目构建时，系统不得包含 Newtonsoft.Json 包引用
4. 当任何转换器处理 JSON 数据时，系统应使用 System.Text.Json 中的 JsonConverter<T> 基类
5. 当系统序列化或反序列化数据时，JSON_Serializer 应处理所有操作而无需 Newtonsoft.Json 回退

### 需求 3: 优化随机数生成

**用户故事:** 作为一名开发人员，我希望使用 Random.Shared 优化随机数生成，以便系统具有更好的性能并减少内存分配。

#### 验收标准

1. 当任何组件需要随机数时，系统应使用 Random.Shared 而不是创建新的 Random 实例
2. 当 GenericTools 生成随机值时，Random_Generator 应使用共享实例
3. 当 DantiaoLayer 处理随机事件时，Random_Generator 应使用共享实例
4. 当 DialogueUI 生成随机元素时，Random_Generator 应使用共享实例
5. 当系统运行时，系统不得创建不必要的 Random 对象分配

### 需求 4: 实现正则源生成

**用户故事:** 作为一名开发人员，我希望实现正则源生成，以便针对 AOT 编译优化正则表达式处理。

#### 验收标准

1. 当 WordTools 处理文本模式时，Regex_Engine 应使用 GeneratedRegex 属性
2. 当 PropertyComparer 执行模式匹配时，Regex_Engine 应使用 GeneratedRegex 属性
3. 当任何组件编译正则模式时，系统应在编译时生成正则代码
4. 当系统处理正则表达式时，Regex_Engine 不得在运行时创建 Regex 实例
5. 当进行 AOT 编译时，系统应在编译输出中包含所有正则模式

### 需求 5: 优化枚举解析

**用户故事:** 作为一名开发人员，我希望优化枚举解析操作，以便系统具有更好的性能和错误处理。

#### 验收标准

1. 当系统从字符串解析枚举值时，系统应使用 Enum.TryParse<T> 而不是 Enum.Parse
2. 当枚举解析失败时，系统应优雅地处理失败而不抛出异常
3. 当系统处理包含枚举值的配置数据时，系统应验证枚举解析结果
4. 当遇到无效的枚举值时，系统应提供有意义的错误消息
5. 当系统执行枚举操作时，系统应尽量减少装箱和拆箱操作

### 需求 6: AOT 兼容性验证

**用户故事:** 作为一名开发人员，我希望进行全面的 AOT 兼容性验证，以便系统在 AOT 部署场景中正常工作。

#### 验收标准

1. 当系统使用 AOT 编译时，系统不得产生裁剪警告
2. 当系统在 AOT 模式下运行时，系统应保持所有功能且无运行时故障
3. 当执行 AOT 分析时，系统应保留所有必需的类型和方法
4. 当系统使用反射时，系统应仅使用符合 AOT 兼容性的反射模式
5. 当包含第三方依赖项时，系统应确保它们兼容 AOT

### 需求 7: 性能优化验证

**用户故事:** 作为一名开发人员，我希望验证性能优化是否有效，以便系统展示出可测量的改进。

#### 验收标准

1. 当测量随机数生成时，系统应显示与之前的实现相比减少了分配开销
2. 当对正则处理进行基准测试时，系统应展示使用源生成模式后的性能提升
3. 当测试枚举解析时，系统应显示使用 TryParse 方法后的更好性能
4. 当分析内存使用情况时，系统应展示减少了垃圾回收压力
5. 当测量启动时间时，系统应显示初始化的性能提升

### 需求 8: 保持向后兼容性

**用户故事:** 作为一名用户，我希望优化后的系统保持现有功能，以便我的存档和配置继续工作。

#### 验收标准

1. 当加载现有的存档文件时，系统应使用新的 JSON 系统正确反序列化数据
2. 当处理配置文件时，系统应保持与现有格式的兼容性
3. 当访问游戏数据时，系统应提供与优化前相同的功能
4. 当显示用户界面时，系统应保持相同的行为和外观
5. 当系统处理旧数据格式时，系统应优雅地处理它们或提供清晰的迁移路径
