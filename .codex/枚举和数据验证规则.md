# 枚举和数据验证规则

**适用范围**: 所有涉及枚举、数据结构、外部数据源的代码修改

---

## 🚫 严格禁止的行为

### 1. 禁止假设枚举值
❌ **错误示例**：
```csharp
// 假设枚举值为 Level1, Level2, Level3...
var name = level switch
{
    MyEnum.Level1 => "初级",  // ❌ 未验证枚举定义
    MyEnum.Level2 => "中级",  // ❌ 可能不存在
    ...
};
```

✅ **正确做法**：
1. 先用 `readFile` 或 `readCode` 查看枚举定义
2. 确认实际的枚举成员名称
3. 再编写代码

### 2. 禁止假设数据结构
❌ **错误示例**：
```csharp
// 假设JSON中有某个字段
var value = data.SomeField;  // ❌ 未验证字段是否存在
```

✅ **正确做法**：
1. 先用 `executePwsh` 或 `readFile` 查看实际数据
2. 确认字段名称、类型、可能的值
3. 再编写代码

---

## ✅ 强制执行的流程

### 修改涉及枚举的代码时

**必须按此顺序执行**：

1. **查看枚举定义**
   ```
   readFile: 查看枚举所在的 .cs 文件
   或
   readCode: 查看枚举定义
   ```

2. **验证数据源**
   ```
   executePwsh: 查看 JSON/XML 中的实际数据
   或
   grepSearch: 搜索枚举的使用场景
   ```

3. **编写代码**
   - 使用实际的枚举成员名称
   - 不要基于命名模式假设

4. **再次验证**
   - 确认枚举值和数据匹配
   - 检查是否有遗漏的枚举成员

### 修改涉及外部数据的代码时

**必须按此顺序执行**：

1. **追溯数据源**
   ```
   找到数据文件（JSON/XML/数据库）
   查看实际的数据结构和值
   ```

2. **验证字段存在性**
   ```
   确认字段名称（大小写敏感）
   确认字段类型
   确认可能的值范围
   ```

3. **编写代码**
   - 使用实际的字段名称
   - 考虑字段可能为 null 的情况（但不是防御性检查）

4. **数据映射验证**
   - 确认代码逻辑和数据匹配
   - 测试边界情况

## 📋 检查清单

在提交代码前，必须确认：

### 枚举相关
- [ ] 已查看枚举定义文件
- [ ] 使用的枚举成员名称与定义完全一致
- [ ] 已验证数据源中的枚举值
- [ ] Switch表达式覆盖了所有可能的枚举值
- [ ] 有默认分支 `_` 处理未知情况

### 数据结构相关
- [ ] 已查看数据源文件（JSON/XML）
- [ ] 字段名称与数据源完全一致（大小写）
- [ ] 已考虑字段可能为 null 的情况
- [ ] 已验证字段类型匹配
- [ ] 已测试实际数据

## 🎓 常见错误模式

### 错误模式1: 基于命名习惯假设

```csharp
// ❌ 假设枚举遵循 Level1, Level2 模式
MyEnum.Level1  // 可能实际是 MyEnum.低, MyEnum.中, MyEnum.高

// ❌ 假设字段名为驼峰命名
data.firstName  // 可能实际是 data.FirstName 或 data.first_name
```

### 错误模式2: 忽略本地化

```csharp
// ❌ 假设枚举是英文
MyEnum.Low, MyEnum.Medium, MyEnum.High

// ✅ 实际可能是中文
MyEnum.低, MyEnum.中, MyEnum.高
```

### 错误模式3: 不验证数据范围

```csharp
// ❌ 假设枚举值从1开始
var level = (MyEnum)1;  // 可能实际从0开始

// ✅ 应该查看枚举定义确认
public enum MyEnum
{
    未知,  // 0
    低,    // 1
    中,    // 2
    高     // 3
}
```

## 🔧 工具使用指南

### 查看枚举定义
```bash
# 方法1: 直接读取文件
readFile: path/to/EnumFile.cs

# 方法2: 搜索枚举定义
grepSearch: "enum MyEnumName"

# 方法3: 使用readCode
readCode: path/to/EnumFile.cs, selector: "MyEnumName"
```

### 验证数据源
```bash
# 方法1: 查看JSON数据
executePwsh: Get-Content "data.json" | ConvertFrom-Json | Select-Object Field1, Field2

# 方法2: 搜索特定字段
grepSearch: '"FieldName":\s*\d+' in data.json

# 方法3: 统计枚举值分布
executePwsh: (Get-Content "data.json" | ConvertFrom-Json).Items | Group-Object EnumField
```

## 📝 实际案例

### 案例: InformationLevel 枚举错误

**错误**：
```csharp
// 假设的枚举值（错误）
InformationLevel.Level1 => "初级"
InformationLevel.Level2 => "低级"
InformationLevel.Level3 => "中级"
```

**实际定义**：
```csharp
public enum InformationLevel
{
    未知,  // 0
    无,    // 1
    低,    // 2
    中,    // 3
    高,    // 4
    全     // 5
}
```

**教训**：
1. ❌ 没有先查看枚举定义
2. ❌ 基于常见命名模式假设
3. ❌ 没有验证数据源

**正确流程**：
1. ✅ `readFile: InformationLevel.cs` 查看定义
2. ✅ `executePwsh: 查看 CommonData.json` 验证数据
3. ✅ 使用实际枚举值编写代码
4. ✅ 验证映射关系

## 🎯 核心原则

### 验证优先于假设
- **永远先验证，再编码**
- **不要基于经验假设数据结构**
- **使用工具查看实际定义**

### 数据驱动开发
- **代码必须匹配数据源**
- **枚举值必须与定义一致**
- **字段名必须与数据文件一致**

### 追溯而非猜测
- **遇到枚举，追溯定义文件**
- **遇到数据，追溯数据源**
- **遇到配置，追溯配置文件**

---

## ⚠️ 违规后果

违反这些规则会导致：
1. 🔴 **编译错误** - 使用不存在的枚举成员
2. 🔴 **运行时错误** - 访问不存在的字段
3. 🔴 **逻辑错误** - 枚举值映射错误
4. 🔴 **数据不匹配** - 代码和数据源不一致
