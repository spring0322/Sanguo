# 数据加载问题诊断规范

**日期：** 2026-03-18  
**状态：** 强制执行  
**原因：** 避免基于假设猜测数据结构，必须查看实际数据

---

## 🚨 核心原则

### ✅ 正确的诊断流程

```
1. 查看实际数据文件（JSON/XML）
   ↓
2. 确认字段名和数据结构
   ↓
3. 对比 DTO 定义
   ↓
4. 检查反序列化逻辑
   ↓
5. 修复字段映射或数据流
```

### ❌ 错误的诊断流程

```
1. 假设数据结构
   ↓
2. 基于假设编写代码
   ↓
3. 代码不工作
   ↓
4. 继续猜测其他可能性
   ↓
5. 反复失败
```

## 📋 案例研究：人物宝物显示问题

### 错误的诊断过程（反面教材）

#### 第 1 次错误：假设 Person.TreasureIDs 存在

**错误操作：**
```csharp
// ❌ 没有查看实际数据，直接假设字段存在
foreach (Person person in this.Persons)
{
    if (person.TreasureIDs != null && person.TreasureIDs.Count > 0)
    {
        // 基于假设编写代码...
    }
}
```

**问题：**
- 没有打开 `Content/Data/Scenario/184DHZS.json` 查看实际数据
- 假设新剧本使用 `Person.TreasureIDs` 字段
- 实际上这个字段根本不存在

**后果：**
- 编写了大量无用代码
- 浪费时间和精力
- 问题依然存在

#### 第 2 次错误：添加防御性空检查


**错误操作：**
```csharp
// ❌ 添加防御性空检查来掩盖数据错误
if (this.AllPersons.TryGetValue(treasure.BelongedPersonIDString, out var person))
{
    // 处理...
}
else
{
    // 记录警告，但没有追溯根本原因
    System.Diagnostics.Debug.WriteLine($"⚠️ 警告：...");
}
```

**问题：**
- 没有追溯为什么 `BelongedPersonIDString` 是 -1
- 假设是数据加载逻辑的问题
- 实际上是反序列化字段名不匹配

**后果：**
- 掩盖了真正的问题
- 问题依然存在

#### 第 3 次错误：添加诊断日志但不查看数据

**错误操作：**
```csharp
// ❌ 添加日志，但仍然不查看实际数据文件
#if DEBUG
System.Diagnostics.Debug.WriteLine($"[LoadTreasureFromDTO] dto.BelongedPersonID={dto.BelongedPersonID}");
#endif
```

**问题：**
- 日志显示 `dto.BelongedPersonID=-1`
- 但仍然没有打开 JSON 文件查看实际数据
- 继续猜测是数据加载逻辑的问题

**后果：**
- 反复尝试不同的修复方案
- 浪费大量时间

### 正确的诊断过程（正面示范）

#### 步骤 1：查看实际数据文件

**操作：**
```bash
# 打开剧本数据文件
code Content/Data/Scenario/184DHZS.json

# 搜索宝物数据
grep -A 10 '"ID": 302' Content/Data/Scenario/184DHZS.json
```

**发现：**
```json
{
  "ID": 302,
  "Name": "绝影",
  "BelongedPersonIDString": 343,  // ← 字段名是 "BelongedPersonIDString"
  "HidePlaceIDString": -1
}
```

#### 步骤 2：对比 DTO 定义

**查看 TreasureDTO.cs：**
```csharp
public class TreasureDTO
{
    public int BelongedPersonID { get; set; } = -1;  // ← 字段名是 "BelongedPersonID"（缺少 "String" 后缀）
}
```

#### 步骤 3：确认根本原因

**问题：**
- JSON 字段名：`BelongedPersonIDString`
- DTO 属性名：`BelongedPersonID`
- System.Text.Json 无法匹配字段名
- 反序列化时使用默认值 `-1`

#### 步骤 4：修复

**解决方案：**
```csharp
// ✅ 使用 JsonPropertyName 特性映射字段名
[JsonPropertyName("BelongedPersonIDString")]
public int BelongedPersonID { get; set; } = -1;
```

## 🔧 强制执行的诊断流程

### 当遇到数据加载问题时，必须按以下步骤操作：

#### 步骤 1：查看实际数据文件（强制）

**工具：**
```bash
# 查看 JSON 数据
code Content/Data/Scenario/184DHZS.json

# 搜索特定对象
grep -A 20 '"ID": 343' Content/Data/Scenario/184DHZS.json

# 搜索特定字段
grep "BelongedPersonID" Content/Data/Scenario/184DHZS.json
```

**检查清单：**
- ✅ 字段名是什么？（精确到大小写）
- ✅ 字段值是什么？（-1 还是有效值）
- ✅ 字段是否存在？（不要假设）
- ✅ 数据结构是什么？（对象、数组、字符串）

#### 步骤 2：对比 DTO 定义

**查看 DTO 文件：**
```csharp
// WorldOfTheThreeKingdoms/Serialization/DTOs/TreasureDTO.cs
public class TreasureDTO
{
    public int BelongedPersonID { get; set; }  // ← 属性名
}
```

**检查清单：**
- ✅ DTO 属性名是否与 JSON 字段名完全匹配？
- ✅ 是否有 `[JsonPropertyName]` 特性？
- ✅ 数据类型是否匹配？（int vs string）
- ✅ 是否有默认值？

#### 步骤 3：检查反序列化逻辑

**查看反序列化代码：**
```csharp
// LoadDataPhase.cs
var treasure = new Treasure
{
    BelongedPersonIDString = dto.BelongedPersonID,  // ← 字段映射
};
```

**检查清单：**
- ✅ DTO 属性是否正确映射到实体字段？
- ✅ 是否有类型转换错误？
- ✅ 是否有空值处理？

#### 步骤 4：验证数据流

**添加诊断日志：**
```csharp
#if DEBUG
System.Diagnostics.Debug.WriteLine($"[JSON] BelongedPersonIDString={jsonValue}");
System.Diagnostics.Debug.WriteLine($"[DTO] BelongedPersonID={dto.BelongedPersonID}");
System.Diagnostics.Debug.WriteLine($"[Entity] BelongedPersonIDString={treasure.BelongedPersonIDString}");
#endif
```

**检查清单：**
- ✅ JSON 值是否正确？
- ✅ DTO 值是否正确？
- ✅ 实体值是否正确？
- ✅ 哪一步出现了问题？

## ⚠️ 禁止的操作

### 1. 禁止假设数据结构

**❌ 错误：**
```csharp
// 假设 Person.TreasureIDs 字段存在
if (person.TreasureIDs != null)
{
    // ...
}
```

**✅ 正确：**
```bash
# 先查看实际数据
grep -A 50 '"ID": 343' Content/Data/Scenario/184DHZS.json | grep -i treasure
```

### 2. 禁止添加防御性空检查来掩盖问题

**❌ 错误：**
```csharp
// 添加空检查，但不追溯根本原因
if (treasure.BelongedPersonIDString >= 0)
{
    if (this.AllPersons.TryGetValue(treasure.BelongedPersonIDString, out var person))
    {
        // ...
    }
    else
    {
        // 记录警告，但没有追溯为什么 BelongedPersonIDString 是 -1
        System.Diagnostics.Debug.WriteLine($"⚠️ 警告：...");
    }
}
```

**✅ 正确：**
```bash
# 追溯根本原因：为什么 BelongedPersonIDString 是 -1？
# 1. 查看 JSON 数据
# 2. 查看 DTO 定义
# 3. 查看反序列化逻辑
# 4. 找到字段名不匹配的问题
```

### 3. 禁止基于假设编写大量代码

**❌ 错误：**
```csharp
// 假设新剧本使用 Person.TreasureIDs，编写大量代码
foreach (Person person in this.Persons)
{
    if (person.TreasureIDs != null && person.TreasureIDs.Count > 0)
    {
        foreach (int treasureID in person.TreasureIDs)
        {
            // 50 行代码...
        }
    }
}
```

**✅ 正确：**
```bash
# 先查看实际数据，确认字段是否存在
grep -A 50 '"ID": 343' Content/Data/Scenario/184DHZS.json
# 发现：Person 数据中没有 TreasureIDs 字段
# 结论：不要编写这段代码
```

## 🎯 关键教训

### 1. 不要猜测，查看实际数据

**错误心态：**
- "我觉得数据应该是这样的"
- "新剧本可能使用了新字段"
- "让我试试这个方案"

**正确心态：**
- "让我打开数据文件看看"
- "实际的字段名是什么？"
- "数据结构到底是什么样的？"

### 2. 字段名必须精确匹配

**System.Text.Json 反序列化规则：**
- 默认区分大小写
- 字段名必须完全匹配
- 不匹配的字段使用默认值（不会报错）

**解决方案：**
- 使用 `[JsonPropertyName]` 特性
- 或者修改 DTO 属性名以匹配 JSON 字段名

### 3. 追溯根本原因，不要掩盖问题

**错误做法：**
- 添加防御性空检查
- 记录警告日志
- 继续运行

**正确做法：**
- 追溯为什么值是 null 或 -1
- 查看数据源（JSON 文件）
- 找到根本原因并修复
