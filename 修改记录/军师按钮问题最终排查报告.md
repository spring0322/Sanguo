# 军师按钮问题最终排查报告

## 问题症状
用户反馈军师按钮点击没有效果，无法正常任命军师。

## 根本原因分析

### 主要问题：菜单显示条件
经过深入排查，发现问题的根本原因是**菜单显示条件**。

在 `Content/Data/Plugins/ContextMenuData.xml` 中：
```xml
<MenuItem ID="1" Name="Person_Appointment_AppointAdvisor" DisplayName="任命" DisplayIfTrue="CanAppointAdvisor" />
```

"任命"菜单项有显示条件 `DisplayIfTrue="CanAppointAdvisor"`，这意味着：
- 如果 `Architecture.CanAppointAdvisor()` 返回 `false`，菜单项根本不会显示
- 用户看不到"任命"选项，自然无法点击

### 显示条件的具体要求
`CanAppointAdvisor()` 方法要求同时满足：
1. **势力有君主** 且 **君主未被俘虏**
2. **是玩家势力** 且 **有合适的候选人**
3. **候选人条件**：
   - 不是君主
   - 不是当前军师
   - 人物可用 (`Available = true`)
   - 人物存活 (`Alive = true`)
   - 未被俘虏 (`BelongedCaptive = null`)
   - 不在部队中 (`LocationTroop = null`)
   - **智力 >= 70** ⭐ **关键条件**

### 最可能的原因
**智力要求过高**：原始代码要求候选人智力 >= 70，这个要求可能过于严格，导致很多情况下没有合适的候选人。

## 解决方案

### 1. 临时解决方案（已实施）
降低智力要求从70到60：
```csharp
// 在 Faction.cs 的 AdvisorCandicate 属性中
if (p != this.Leader && p != this.Advisor && p.Available && p.Alive && 
    p.BelongedCaptive == null && p.LocationTroop == null && p.Intelligence >= 60) // 从70改为60
```

### 2. 永久解决方案选项

#### 选项A：移除显示条件
```xml
<!-- 移除 DisplayIfTrue="CanAppointAdvisor" -->
<MenuItem ID="1" Name="Person_Appointment_AppointAdvisor" DisplayName="任命" />
```
**优点**：菜单始终显示，用户体验更好
**缺点**：点击后可能显示空列表

#### 选项B：使用更宽松的显示条件
```xml
<!-- 使用包含已有军师的条件 -->
<MenuItem ID="1" Name="Person_Appointment_AppointAdvisor" DisplayName="任命" DisplayIfTrue="CanAppointAdvisorOrHasAdvisor" />
```
**优点**：有军师时也能重新任命
**缺点**：仍可能因为没有候选人而不显示

#### 选项C：调整智力要求
保持显示条件，但降低智力要求到合理水平（如60或65）。
