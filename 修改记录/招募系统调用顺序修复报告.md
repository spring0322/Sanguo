# 招募系统调用顺序修复报告

## 问题诊断

### 发现的问题
从用户提供的调试日志可以看出：
```
[招募操作] 最终状态 - PersonalLoyalty: 4, Loyalty: 0, TempLoyaltyChange: 800
[招募操作] 武将 诸葛亮 已加入势力 刘备，当前忠诚度: 0
```

即使TempLoyaltyChange设置为800，忠诚度仍然是0，说明调用顺序有问题。

### 根本原因
在`AdvisorAdviceEventSystem.cs`的`PerformRecruitment`方法中，调用顺序错误：

**错误的顺序**:
1. 先计算忠诚度
2. 先设置TempLoyaltyChange
3. 后调用MoveToArchitecture加入势力

**正确的顺序应该是**:
1. 先让武将加入势力（设置BelongedFaction）
2. 设置武将状态（Status）
3. 最后设置忠诚度

### 问题分析
`Person.Loyalty`属性的getter可能包含这样的逻辑：
```csharp
public int Loyalty
{
    get
    {
        if (BelongedFaction == null) return 0; // 在野武将忠诚度为0
        // 其他计算逻辑...
    }
}
```

因此，在武将尚未加入势力时，无论TempLoyaltyChange设置为多少，Loyalty都会返回0。

## 修复方案

### 1. 修复AdvisorAdviceEventSystem
**文件**: `WorldOfTheThreeKingdoms/GameManager/AdvisorAdviceEventSystem.cs`

**修复内容**:
- 将`PerformRecruitment`方法重构为调用`PersonRecruitmentHandler.DirectJoinLogic`
- 确保使用正确的操作顺序
- 移除旧的错误实现

**修复前**:
```csharp
// 错误：先设置忠诚度，后加入势力
person.TempLoyaltyChange = calculatedLoyalty + 200;
person.MoveToArchitecture(faction.Capital);
```

**修复后**:
```csharp
// 正确：使用PersonRecruitmentHandler的正确流程
bool success = PersonRecruitmentHandler.DirectJoinLogic(
    faction, person, recruiter, RecruitMethod.Recommendation);
```

### 2. PersonRecruitmentHandler的正确流程
**文件**: `WorldOfTheThreeKingdoms/GameManager/PersonRecruitmentHandler.cs`

**正确的操作顺序**:
```csharp
// 1. 先确立归属关系
faction.AddPerson(talent);

// 2. 设置武将状态
talent.Status = PersonStatus.General;
talent.Location = recruiter.Location;

// 3. 最后计算并应用忠诚度
int finalLoyalty = RecruitmentCalculator.CalculateInitialLoyalty(...);
SetPersonLoyalty(talent, finalLoyalty);
```
